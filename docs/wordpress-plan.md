# WordPress CMS化の設計メモ

「お店の方が自分で更新できるようにする」ための移行プランです。
**まだ実装はしていません。**着手のご指示をいただければこの方針で進めます。

---

## 1. どこを更新できるようにするか

まず「誰が・何を・どのくらいの頻度で更新するか」を整理しました。
全部を編集可能にすると管理画面が複雑になり、かえって使われなくなります。
**更新頻度の高いものだけをCMS化**し、それ以外は固定にするのがおすすめです。

| 内容 | 更新頻度 | 対応 |
|---|---|---|
| お知らせ・ブログ | 高い | 投稿（標準機能） |
| どうぶつの紹介 | 中くらい | カスタム投稿タイプ |
| 営業時間・臨時休業 | 中くらい | テーマ設定（1か所で管理） |
| メニュー・料金 | 低い | カスタム投稿タイプ（または固定ページ） |
| スタッフ紹介 | 低い | カスタム投稿タイプ |
| 店舗紹介・ルール・アクセスの本文 | ほぼ変わらない | 固定ページ |
| デザイン・レイアウト | 変わらない | テーマファイル（固定） |

## 2. ファイルの対応関係

現在の静的HTMLは、共通部分（ヘッダー・フッター）を1か所で管理して
全ページに書き出す作り方をしています。これは WordPress の
`get_header()` / `get_footer()` とほぼ同じ考え方なので、**移行はそのまま置き換えられます。**

```
【現在】                      【WordPress】
共通ヘッダー           →     header.php
共通フッター           →     footer.php
共通のSVGシンボル      →     template-parts/svg-defs.php

index.html            →     front-page.php        トップ
about.html            →     page-about.php        店舗紹介（固定ページ）
rules.html            →     page-rules.php        ご利用ルール（固定ページ）
access.html           →     page-access.php       アクセス（固定ページ）
sales.html            →     page-sales.php        生体販売（固定ページ）

animals.html          →     archive-animal.php    どうぶつ一覧
animal.html           →     single-animal.php     どうぶつ個別
news.html             →     home.php / archive.php お知らせ一覧
（お知らせ個別）        →     single.php            お知らせ個別 ※新規に必要

css/style.css         →     そのまま（wp_enqueue_style で読み込み）
css/animations.css    →     そのまま
js/main.js            →     そのまま（wp_enqueue_script で読み込み）
images/logo.jpg       →     テーマ内 or カスタマイザーのロゴ設定
```

**CSSとJavaScriptは一切変更せずそのまま使えます。** クラス名の付け方を
CMS化しやすいように統一してあるためです。

## 3. カスタム投稿タイプ

### どうぶつ（`animal`）

一覧ページの絞り込みチップは、現在 `data-cat` 属性で動かしています。
これを**カテゴリー（タクソノミー）に置き換える**だけで、
お店の方が管理画面からカテゴリーを増やせるようになります。

- タクソノミー `animal_cat`：爬虫類／鳥類・猛禽類／小動物・うさぎ／犬・猫・サル
- タクソノミー `animal_status`：販売中／ふれあい可／餌やり体験／見学のみ（タグ表示に対応）

カスタムフィールド（ACF などで設定）：

| 項目 | 種類 | 例 |
|---|---|---|
| 英語表記 | テキスト | REPTILE |
| 別名 | テキスト | レオパードゲッコー |
| 分類 | テキスト | トカゲモドキ科 |
| 生息地 | テキスト | 中央アジアの乾燥地帯 |
| 大きさ | テキスト | 20〜25cm |
| 寿命 | テキスト | 10〜15年 |
| 写真 | 画像（複数） | メイン＋サムネイル3〜4枚 |
| POPカード画像 | 画像 | 店内掲示のカード |
| 紹介文 | テキストエリア | 本文 |

### スタッフ（`staff`）
氏名／担当／写真／ひとこと の4項目だけ。シンプルに保ちます。

### メニュー（`menu_item`）
品名／価格／区分（ドリンク・ご飯物・ケーキ・体験）。
※更新頻度が低ければ、固定ページに直接書く形でも十分です。

### お知らせ
WordPress標準の「投稿」をそのまま使います。
カテゴリーに 入荷／休業／店内の様子 を用意すれば、現在の絞り込みがそのまま動きます。

## 4. サイト全体で使う情報（テーマ設定）

電話番号・住所・営業時間は**全ページの複数箇所に出てくる**ため、
1か所で直せるようにします（ACF のオプションページ、またはカスタマイザー）。

- 店名／住所／電話番号
- 営業時間／定休日
- 「本日 営業中」の表示 ※後述
- Instagram の URL
- 第一種動物取扱業の登録番号・有効期限
- 第二駐車場の案内文・案内図

これにより、**電話番号が変わっても管理画面で1回直せば全ページに反映**されます。

## 5. 「本日 営業中」の自動表示

現在は「本日　営業中 11:00 – 19:00」が固定文言です。
CMS化する際、ここは**曜日と時刻から自動で切り替える**のがおすすめです。

- 定休日（火曜）→「本日は定休日です」
- 営業時間内 →「営業中 11:00 – 19:00」
- 営業時間外 →「本日の営業は終了しました」
- 臨時休業日を登録できるようにし、その日は「臨時休業」と表示

お客様が来店前に必ず見る情報なので、自動化すると更新漏れによる
トラブル（閉まっているのに営業中と表示）を防げます。

## 6. 進め方の目安

| 段階 | 内容 |
|---|---|
| 1 | テーマの土台（header / footer / functions.php / CSS・JS読み込み） |
| 2 | 固定ページ4枚（店舗紹介・ルール・アクセス・生体販売） |
| 3 | お知らせ（一覧・個別・カテゴリー絞り込み） |
| 4 | どうぶつ（カスタム投稿タイプ・一覧・個別・絞り込み） |
| 5 | テーマ設定（店舗情報の一元管理）＋営業状況の自動表示 |
| 6 | トップページの組み立て（各所から最新情報を引っ張る） |
| 7 | 管理画面の使い方メモ作成 |

## 7. あわせてご検討いただきたい点

- **サーバーとドメイン**：WordPress が動くサーバーが必要です（レンタルサーバーで可）。
  現在の静的HTMLのままなら、無料のホスティングでも公開できます。
- **静的のままという選択肢**：更新が月1回程度なら、HTMLを直接編集するか、
  お知らせだけ別サービス（microCMS など）を使う方が、
  維持費・セキュリティ対策の手間ともに軽くなります。
- **セキュリティ**：WordPress は定期的な更新が必要です。放置すると乗っ取りの
  リスクがあるため、更新を誰が行うかを決めておく必要があります。
